# День 20 — оркестрация MCP

MrKai — терминальный агент с тремя MCP-серверами: `mrkPipeline` (локальные документы и отчёты), `mrkScheduler` (напоминания), `mrkGitlab` (открытые MR). Агент обнаруживает схемы инструментов и передаёт их модели. Модель выбирает инструменты, получает результат каждого вызова и решает следующий шаг. Имена содержат сервер, поэтому одинаковые названия не смешиваются. Длинный запрос может пройти через несколько серверов за один ход диалога.

Например: «Найди материалы про MCP, вызови отдельно поиск и обработку, сохрани выдержку в orchestration.md. После успешного сохранения напомни через 60 секунд проверить этот отчёт и проверь список напоминаний». Порядок определяется зависимостями и выбором модели; готовой жёстко заданной цепочки для этого запроса нет.

## Установка и запуск

Нужен Go 1.21+. В каталоге `aiac9/d20`:

```sh
export PATH="$PWD:$PATH"
mrkai
```

`mrkai` собирает и запускает приложение; доступен также `./mrkai`. По умолчанию запускается обычный чат. Планирование включается только через `/plan-mode enable`.

Для естественного языка задайте `DEEPSEEK_API_KEY`. Дополнительные настройки: `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`, `AGENT_SYSTEM_PROMPT`. Прямые команды MCP работают без ключа модели. GitLab требует `GITLAB_API_TOKEN`; адрес API меняется через `GITLAB_API_URL`. Ключи задаются окружением; файлы с секретами не нужны.

`KNOWLEDGE_DIR` задаёт каталог документов (по умолчанию `./knowledge`), `DATA_DIR` — данные (по умолчанию `./data`), `INVARIANTS_FILE` — файл инвариантов. Поиск читает верхний уровень каталога: обычные незакрытые `.md`/`.txt` до 64 КиБ. Отчёты сохраняются в `data/reports`, повторное имя заменяет отчёт. Выдержка состоит из первых трёх содержательных строк, без отдельной LLM-суммаризации.

## Команды

- `/info`, `/help` — полная справка; `/mcp`, `/mcp list` — серверы и количество инструментов.
- `/mcp mrkpipeline`, `/mcp mrkpipeline tools` — инструменты документов.
- `/mcp mrkpipeline run MCP | report.md` — композиция внутри одного сервера.
- `/mcp mrkpipeline call NAME JSON` — отдельные `search`, `summarize`, `save_to_file`, `run_pipeline`.
- `/mcp mrkgitlab tools`, `/mcp mrkgitlab mrs`, `/mcp mrkgitlab call list_open_merge_requests {}` — GitLab.
- `/mcp mrkscheduler tools`, `add СЕКУНДЫ ПЕРИОД ТЕКСТ`, `mrs ПЕРИОД [ПРОЕКТ]`, `list`, `summary`, `cancel ID` — подкоманды планировщика с префиксом `/mcp mrkscheduler`.
- `/plan-mode enable`, `/plan-mode disable`, `/state`, `/pause`, `/resume`, `/reset` — управление задачей. `/reset` также отменяет задания планировщика.
- `/invariants`, `/invariant add ТЕКСТ`, `/invariant remove ID`, `/invariant clear` — инварианты.
- `/exit`, `/quit` — выход.

Команды и подкоманды доступны через автодополнение. Терминал показывает обнаружение инструментов, номер шага модели, сервер, инструмент и завершение вызова. Максимум 16 ответов модели и 48 вызовов инструментов за ход; превышение завершает ход явной ошибкой. Уже выполненные действия не откатываются, поэтому перед повтором проверьте отчёты и напоминания.

Поддерживается нужное для встроенных серверов подмножество MCP: stdio, версия `2025-06-18`, initialize, tools/list, tools/call, текстовые результаты и уведомления. Произвольные внешние серверы, пагинация инструментов и HTTP-транспорт не настраиваются. Модель может ошибиться в выборе или аргументах; ошибки инструментов возвращаются ей для исправления. Офлайн-тесты проверяют маршрутизацию и передачу данных со сценарной моделью, качество выбора реальной модели требует запуска с ключом.

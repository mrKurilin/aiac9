# День 10 — управление контекстом и ветки диалога

Терминальный `mrkai` поддерживает Sliding Window и Sticky Facts / Key-Value
Memory. Ветки доступны при обоих типах памяти. Сохранены потоковые ответы,
Markdown, редактирование ввода, JSON-сессии, учёт токенов и стоимости.

## Запуск

Нужны Go 1.21+ и `DEEPSEEK_API_KEY`, заданный в окружении терминала.

```sh
cd aiac9/d10
export PATH="$PWD:$PATH"
mrkai
```

`mrkai` — launcher, собирающий и запускающий Go-код. Дополнительный вариант
из каталога дня — `./mrkai`. Параметров запуска нет: команды и выбор настроек
доступны внутри чата через `/`.

### Веб-интерфейс

Тот же функционал (обе панели, все команды и `/sendNext`) доступен в браузере:

```sh
cd aiac9/d10
export DEEPSEEK_API_KEY=...
go run . web
# или, если бинарник уже собран:
mrkai web
```

По умолчанию сервер слушает `http://localhost:8080`; адрес меняется переменной
`WEB_ADDR` (например, `WEB_ADDR=:3000`). Память сохраняется в тот же `DATA_DIR`,
что и у терминальной версии — не запускайте оба режима одновременно с одной
директорией данных. Команды вводятся тем же текстом, что и в терминале
(`/contextManagementStrategy`, `/addBranch`, `/branch`, `/checkpoint`, `/memory`,
`/facts`, `/context`, `/stats`, `/fill`, `/overflow`, `/reset`, `/sendNext`,
`/info`); `/` в поле ввода открывает список команд, Tab дополняет, ↑/↓ листают
историю введённых строк.

Новая сессия начинается с ветки `main`, Sliding Window и N=5. При повторном
запуске восстанавливаются активная ветка и её сохранённые настройки. Рабочая
сессия хранится в `data/terminal.json`; для нового разговора есть `/reset`.

## Меню команд

Поле ввода закреплено на последней строке терминала, подсказки появляются над
ним. Ответы и статистика прокручиваются в отдельной верхней области. При
изменении размера окна положение ввода обновляется автоматически.

Экран разделён на две панели: слева Sliding Window, справа Sticky Facts.
Отправленное сообщение уходит обеим стратегиям одинаковым, поэтому оно
показывается один раз — полосой `── ВЫ ──` во всю ширину, а не копией в каждой
колонке. Текст сообщения выровнен по центру и выделен синим, так что ходы
разделены визуально. Под полосой стоят два ответа рядом, выровненные по этому
ходу: колонки сравнивать удобнее, когда в них только то, чем стратегии
различаются. Цвет отключается переменной `NO_COLOR` и в перенаправленном выводе.

Введите `/`: появится список команд. Продолжайте печатать, чтобы отфильтровать
его по префиксу, например `/cont`.

- ↑/↓ — выбрать пункт; длинный список прокручивается;
- Tab — дополнить команду или аргумент;
- Enter — открыть варианты или подтвердить выбранный пункт;
- Esc — закрыть подсказки;
- вне меню ↑/↓ перебирают историю сообщений.

`/contextManagementStrategy` открывает выбор **Sliding Window** или
**Sticky Facts / Key-Value Memory**. После выбора продолжайте обычный диалог.
При необходимости задайте размер окна явно:

```text
/contextManagementStrategy window 6
/contextManagementStrategy facts 6
```

Без N всегда устанавливается **5 сообщений**, даже если до этого было другое
значение. Выбор через меню также устанавливает N=5. В перенаправленном вводе команды без
аргументов печатают доступные варианты; для выбора укажите `window` или `facts`.

## Ветки

`/addBranch <name>` создаёт независимую копию текущей памяти и сразу открывает
новую ветку. `/branch` показывает существующие ветки для выбора стрелками;
активная отмечена. Можно ввести `/branch <name>` напрямую.

```text
/addBranch alternative
/contextManagementStrategy facts
/branch main
```

Каждая ветка хранит собственные сообщения, facts, тип памяти и N. Изменение
настроек или продолжение одной ветки не меняет остальные. Все ветки сохраняются
при перезапуске. Для двух вариантов из одной точки можно сначала сохранить
checkpoint, затем создавать ветки из него:

```text
/checkpoint base
/addBranch economy base
/branch main
/addBranch extended base
```

Checkpoint — неизменяемая копия памяти вместе с настройками. Список checkpoints
виден в `/memory`. Их можно использовать при обоих типах управления контекстом.

## Как устроена память

| Тип | Что отправляется модели |
|---|---|
| Sliding Window | Последние N сообщений; старые сообщения активной ветки отбрасываются. |
| Sticky Facts / Key-Value Memory | Актуальный JSON-блок facts и последние N сообщений. |

System передаётся отдельно. N считает отдельные сообщения пользователя и
ассистента, а не пары. В запросе новый вопрос входит в N; после ответа снова
остаётся максимум N сообщений. При N=0 отправляется только новый вопрос и
system/facts, дословная история не хранится. Память соседних веток и checkpoints
не включается в запрос.

В Sticky Facts перед ответом отдельный LLM-вызов обновляет facts по новому
сообщению, предыдущим фактам и недавнему контексту. Изменённые значения заменяются,
явно отменённые факты удаляются. Максимум 32 ключа, 80 байт на ключ и 2000 байт
на значение. В расходах учитываются оба вызова.

При невалидном JSON, ошибке API, отмене или ошибке диска незавершённый ход
откатывается. Потраченные токены остаются в статистике. Если потоковый ответ
уже показан, но запись не удалась, терминал сообщает об ошибке сохранения.

Смена типа памяти действует только на текущую ветку. Sliding Window очищает
её facts; ранее отброшенные сообщения не восстанавливаются. Другие ветки и
checkpoints остаются доступными. При переходе в Sticky Facts факты начинают
обновляться со следующего пользовательского сообщения.

## Остальные команды и настройки

- `/memory`, `/facts` — состояние памяти и содержимое facts;
- `/context`, `/stats` — заполнение окна, токены и расходы за запуск;
- `/fill N`, `+20%`, `+50%`, `+100%` — учебный наполнитель, подчиняющийся окну;
- `/overflow on|off` — отправлять или блокировать запрос сверх локальной оценки;
- `/reset` — очистить всю сессию, включая все ветки и checkpoints;
- `/sendNext` — отправить следующее сообщение сценария из `10-messages.md`;
  `/sendNext N` — перейти к сообщению N, `/sendNext list` — список с текущей
  позицией, `/sendNext reset` — начать сценарий заново;
- `/info`, `/exit` — справка и выход.

`/sendNext` отправляет только диалог сценария 1 — 15 сообщений, от «Собираем ТЗ
для проекта «Маяк»…» до «Проверь себя по нашей переписке…». Команды из файла
(`/reset`, `/contextManagementStrategy`, `/facts`, `/branch`), блоки ```` ```sh ````,
шпаргалка «что должно сохраниться» и разделы про ветки в сценарий не попадают:
подготовку прогона вы выполняете сами и осознанно. Сообщение уходит модели так,
как если бы его набрали вручную. Позиция живёт в пределах запуска: после
перезапуска `mrkai` счётчик снова начинается с первого сообщения.
Путь к файлу — `MESSAGES_FILE`, по умолчанию
`../../lectures/неделя_2/TODOs/10-messages.md` относительно рабочего каталога
(и каталога самого бинарника).

`PgUp` / `PgDn` листают диалог на экран назад и вперёд, `/scroll N` — на N строк
(`/scroll -N` — обратно), `/bottom` возвращает к концу. Новый вопрос сам
возвращает панель вниз, чтобы ответ был виден. Заголовки, разделитель,
статистика и подсказка под панелями показаны приглушённым цветом: строка ввода
не сливается с ними.

Строка ввода работает и во время ответа модели: можно печатать не дожидаясь
конца ответа, а `Enter` поставит сообщение в очередь — оно уйдёт следующим ходом.
`↑`/`↓` листают историю ввода, включая команды, так что `/sendNext` повторяется
одной стрелкой вверх.

Имена сессий, веток и checkpoints: 1–64 латинских букв, цифр, `_` или `-`.
Ctrl+U / Ctrl+Backspace очищает строку. Во время запроса Esc отменяет его,
Ctrl+C завершает работу. Команды с `/` не отправляются модели.

Настройки окружения: `DEEPSEEK_MODEL`, `DEEPSEEK_BASE_URL`, `AGENT_SYSTEM_PROMPT`,
`DATA_DIR`, `MESSAGES_FILE`. По умолчанию launcher хранит память в `aiac9/d10/data`.
Ручной лимит ответа не задаётся. Контроль переполнения переключается командой
`/overflow on|off`; по умолчанию отправка сверх локальной оценки разрешена.
Для нестандартного API тарифы можно задать переменными окружения
`DEEPSEEK_INPUT_PRICE`, `DEEPSEEK_CACHED_PRICE`, `DEEPSEEK_OUTPUT_PRICE`
в USD за миллион токенов.

Справочники моделей, лимитов и тарифов унаследованы из d9; актуальность в рамках
d10 не проверялась. Для другого endpoint задайте все три тарифа. До запроса
токены оцениваются приблизительно, после используется usage API, если доступен.
Счётчики общие для запуска и всех веток, не сохраняются между запусками.

Память записывается атомарно с правами 0600; ключ API не записывается.
Прежние сессии d10 автоматически читаются: бывший режим branching становится
Sliding Window с N не меньше сохранённой истории каждой ветки, поэтому перенос
не удаляет сообщения. Новый формат записывается при следующем изменении памяти.
Повреждённые файлы не перезаписываются.

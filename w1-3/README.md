# w1-3 · LLM Playground (DeepSeek) — разные способы рассуждения

Одна логическая/алгоритмическая/аналитическая задача решается через API четырьмя разными стратегиями рассуждения, чтобы сравнить, отличаются ли ответы и какой способ оказался точнее.

## Запуск

```bash
export DEEPSEEK_API_KEY=sk-...
go run .
```

Откройте http://localhost:8080

## Что умеет

- Берёт **одну задачу** (редактируется в верхнем поле) и отправляет её в DeepSeek API (модель `deepseek-chat`, OpenAI-совместимый формат) четырьмя способами, **параллельно**.
- **Сравнение в 4 колонках**: у каждой колонки заголовок фиксированной высоты; видно, какой промпт реально ушёл в API, ответ модели и метаданные (`finish_reason`, число токенов).
- Ответы рендерятся как **Markdown**, формулы LaTeX (`\(…\)`, `\[…\]`, `$…$`, `$$…$$`) набираются через **KaTeX**.
- Страница занимает всю ширину окна.

## Способы рассуждения

| № | Способ                         | Что отправляется в API                                                                           |
|---|--------------------------------|--------------------------------------------------------------------------------------------------|
| 1 | Без подсказок                  | Только условие задачи — прямой ответ модели                                                      |
| 2 | «Решай пошагово»               | К условию дописывается инструкция решать пошагово и объяснять каждый шаг                         |
| 3 | Сначала промпт — потом решение | Два запроса: модель сначала составляет промпт для решения, затем решает по нему                  |
| 4 | Группа экспертов               | Один промпт, в котором аналитик, инженер и критик решают задачу со своих позиций, в конце — итог |

Промпт для каждого способа строится на лету из текста задачи и показан в колонке «Промпт, отправленный в API». Для способа 3 видны оба шага: запрос к модели-составителю и составленный ею промпт.

## API сервера

- `GET /` — веб-интерфейс
- `POST /api/complete` — тело `{"prompt": "...", "system": "...", "params": {...}}`; `system` — необязательное системное сообщение, `params` — произвольные параметры, мержатся поверх сформированного запроса; ответ `{"content": "...", "finish_reason": "...", "prompt_tokens": N, "completion_tokens": N, "total_tokens": N}` или `{"error": "..."}`

## Структура

- `main.go` — HTTP-сервер и прокси к DeepSeek
- `index.html` — веб-интерфейс (встроен в бинарник через `go:embed`); KaTeX подключён с CDN

# День 33 — автосервис, CRM и AI-поддержка

`Гараж 33` — учебный автосервис для развёртывания на VPS. На `/` находится статичный сайт с услугами и контактами, на `/crm` — CRM с колонками **TODO / IN PROGRESS / DONE**. Чат на сайте обслуживает отдельный процесс поддержки: Agent использует FAQ через RAG и получает актуальные данные через MCP.

## Быстрый запуск на VPS

Рекомендуется Ubuntu Server 24.04 LTS, **2 vCPU / 4 ГБ RAM / 40 ГБ SSD**, публичный IPv4 и открытый порт 80. Загрузите каталог `aiac9` с `d33` и `terminal`, затем из `aiac9/d33`:

```sh
sudo bash deploy/bootstrap-vps.sh
```

Скрипт сам установит нужный Docker-стек на свежей Ubuntu, запросит публичный IP, API-ключ и пароль CRM, соберёт и запустит приложения. По умолчанию HTTP; после проверки выведет **`http://ВАШ_IP/`** и **`http://ВАШ_IP/crm`** — адреса для демонстрации. Для HTTPS есть `--https`, для проверки без установки — `--check`. [Все настройки скрипта](deploy/README.md).

## Ручной запуск на VPS

Проект собирается в Docker: Go, компилятор и драйвер SQLite остаются внутри образа. Нужен Docker с Compose 2.17+ и каталог `aiac9` с `d33` и `terminal`. Из `aiac9/d33` задайте переменные окружения:

```sh
export MRKAI_SERVICE_KEY=YOUR_SERVICE_KEY_AT_LEAST_32_CHARACTERS
export CRM_ADMIN_PASSWORD=YOUR_CRM_PASSWORD_AT_LEAST_12_CHARACTERS
export DEEPSEEK_API_KEY=YOUR_API_KEY
```

Запуск двух сервисов:

```sh
docker compose --env-file /dev/null up -d --build
```

Сайт доступен на `http://127.0.0.1:8080/`, CRM — на `http://127.0.0.1:8080/crm`. Вход сотрудника: `admin` и `CRM_ADMIN_PASSWORD`. Для публичного HTTPS задайте домен и включите Caddy:

```sh
export SITE_DOMAIN=garage.example.com
docker compose --env-file /dev/null --profile public up -d --build
```

Замените пример домена своим. DNS должен указывать на VPS; нужны открытые порты 80 и 443. Подробности запуска и хранения данных: [deploy/README.md](deploy/README.md).

## Сайт и CRM

- Сайт: услуги, контакты, две позиции запчастей и чат поддержки.
- CRM: поиск обращений, создание задачи сотрудником, редактирование заголовка и заметок, перенос между колонками мышью или выбором статуса.
- Нерешённые вопросы создают TODO: номер пользователя, причина, переписка, документы и конкретные функции/таблицы для проверки в коде.
- Повторный вопрос по тому же телефону обновляет контекст активной задачи, сохраняя заметки сотрудника. После DONE новое обращение может создать отдельную задачу.
- Новый диалог очищает активный чат, сохраняя задачи и историю в БД.

Контакты автосервиса и состояния доступа — примеры. Проверка номера показывает диагностическое состояние, а не выполняет настоящий вход или подтверждение личности. Остатки и состояния находятся в SQLite; FAQ не подменяет их.

## Конфигурация

`DEEPSEEK_BASE_URL` — URL chat completions, по умолчанию `https://api.deepseek.com/chat/completions`; `DEEPSEEK_MODEL` — по умолчанию `deepseek-chat`. Ключ задаётся только в окружении.

Без Docker отдельные процессы запускаются командами `mrkai web` и `mrkai support` из d33. Нужны уже доступные Go с CGO и C-компилятор. Скрипт `mrkai` есть в каталоге; добавьте его в PATH командой `export PATH="$PWD:$PATH"`. `WEB_ADDR` и `SUPPORT_ADDR` по умолчанию слушают только localhost на портах 8080 и 8081. `CRM_URL` и `SUPPORT_URL` задают адреса связи; `CRM_DB_PATH` — путь к SQLite; `SUPPORT_DATA_DIR` — каталог RAG-индекса; `MRKAI_PROJECT_ROOT` — каталог документации.

Просто `mrkai` сохраняет терминальный интерфейс d22 и учебную работу с JSON-тикетами: `/support ID ВОПРОС`, `/ticket ID`, `/index build`, `/index status`, `/mcp tools`, `/help`, `/reset`, `/clear`, `/exit`, `/quit`. Все команды доступны через автодополнение. Веб-CRM и автоматическая эскалация работают в двух сервисах выше.

## Границы

RAG — локальный лексический поиск по Markdown с разделением по заголовкам. Сервис поддержки использует MCP Streamable HTTP с JSON-ответами: initialize, notifications/initialized, tools/list, tools/call. CRM предоставляет `inventory_list`, `access_check`, `create_support_task`; Agent обнаруживает схемы, разрешает несколько вызовов, возвращает результаты и ошибки модели. Ограничения: 8 шагов модели, 16 вызовов инструментов, до 8 одновременных запросов. SSE, внешняя CRM, SMS-вход, запись на ремонт, оплата и бронь не реализованы.

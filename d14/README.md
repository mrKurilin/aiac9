# День 14 — инварианты и ограничения состояния

MrKai хранит обязательные ограничения отдельно от диалога и проверяет по ним
каждый обычный запрос до генерации ответа. Инвариант может фиксировать
архитектуру, стек, принятое техническое решение или бизнес-правило.

Проверка возвращает по одному явному статусу для каждого правила:
`compatible`, `conflict` или `not_applicable`. Если найден конфликт, основной
LLM-запрос не выполняется, этап задачи не меняется, а терминал показывает
инвариант и причину отказа. Если проверка вернула неполный или некорректный
JSON, агент действует безопасно и блокирует ответ.

Инварианты записываются в `data/invariants.json`, а автомат задачи — отдельно в
`data/task-state.json`. `/reset` очищает задачу и чат, но сохраняет ограничения.

## Установка и запуск

Нужны Go 1.21+ и ключ DeepSeek в окружении.

~~~sh
cd aiac9/d14
chmod +x mrkai
mkdir -p "$HOME/.local/bin"
ln -sf "$PWD/mrkai" "$HOME/.local/bin/mrkai"
export PATH="$HOME/.local/bin:$PATH"
export DEEPSEEK_API_KEY="<ваш-ключ>"
mrkai
~~~

Из каталога дня также доступен `./mrkai`. Основной интерфейс — терминальный;
аргументы и demo-режимы не используются.

## Работа с инвариантами

Добавьте несколько правил до постановки задачи:

~~~text
/invariant add архитектура | Сохранять слоистую архитектуру: domain не зависит от infrastructure
/invariant add стек | Серверная часть пишется только на Go и PostgreSQL
/invariant add бизнес-правило | Оплаченный заказ нельзя удалять
/invariants
~~~

После этого обычный запрос сначала проходит отдельную проверку. Например,
просьба «Перепиши сервер на Python» будет отклонена из-за ограничения стека.
Отказ содержит идентификатор, категорию, текст правила и конкретное объяснение
конфликта. Для удаления правила используется:

~~~text
/invariant remove INV-002
~~~

Удалить сразу все ограничения можно командой:

~~~text
/invariant clear
~~~

Она очищает только отдельное хранилище инвариантов и не изменяет активную
задачу или её диалог.

Проверка семантическая и выполняется моделью, но решение о продолжении принимает
Go-код: основной ответ разрешается только после валидной проверки всех
инвариантов в заданном порядке. Текст проверки не добавляется в диалог и не
подменяет пользовательский запрос.

## Команды

~~~text
/state
/invariants
/invariant add КАТЕГОРИЯ | ПРАВИЛО
/invariant remove ID
/invariant clear
/pause [ПРИЧИНА]
/resume
/reset
/info
/exit
~~~

Автомат задачи унаследован из d13: `planning → execution → validation → done`,
с возвратами `execution → planning` и `validation → execution`. Перед
`planning → execution` по-прежнему требуется явное утверждение плана.

## Конфигурация

- `DEEPSEEK_API_KEY` — обязательный ключ;
- `DEEPSEEK_MODEL` — модель, по умолчанию `deepseek-chat`;
- `DEEPSEEK_BASE_URL` — OpenAI-совместимый endpoint DeepSeek;
- `AGENT_SYSTEM_PROMPT` — общая системная инструкция основного агента;
- `DATA_DIR` — каталог данных, по умолчанию `./data`;
- `INVARIANTS_FILE` — отдельный путь к JSON с инвариантами, по умолчанию
  `DATA_DIR/invariants.json`.

Оба файла состояния записываются атомарно с правами `0600`. Не вводите в
инварианты и диалог ключи, пароли и другие секреты.

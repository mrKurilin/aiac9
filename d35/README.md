# День 35 — AI-помощник для поиска авиабилетов по России и миру

Основной запуск — **чат `mrkai` в терминале**, без деплоя, сервера и токена Telegram. Напишите: «Из Казани в Сочи в ноябре, туда-обратно на 5–7 дней, до 20000 рублей, без пересадок». DeepSeek разберёт запрос и уточнит недостающие условия. Программа получит предложения Aviasales через Travelpayouts Data API, проверит даты, бюджет, длительность и пересадки, покажет до пяти вариантов со ссылками. Можно продолжить: «А если с пересадкой?».

## Запуск

Нужен Go 1.21+ и полный checkout `aiac9`: общий пакет `terminal` должен находиться рядом с `d35`. Подготовьте API-токен [Travelpayouts](https://www.travelpayouts.com/) с подключённой программой Aviasales и API-ключ [DeepSeek](https://platform.deepseek.com/) с доступным балансом.

Где получить ключи:

- `TRAVELPAYOUTS_TOKEN` — [API-токен в профиле Travelpayouts](https://app.travelpayouts.com/profile/api-token). Зарегистрируйтесь и подключите программу Aviasales для доступа к Data API.
- `DEEPSEEK_API_KEY` — [API keys в кабинете DeepSeek](https://platform.deepseek.com/api_keys). Создайте ключ и убедитесь, что на API-балансе есть средства.

Из каталога `d35` добавьте launcher в PATH:

```sh
export PATH="$PWD:$PATH"
```

Запустите:

```sh
mrkai
```

Launcher скрыто запросит **только два ключа**: Travelpayouts и DeepSeek. Они используются в памяти процесса и не сохраняются в файлы. Если `TRAVELPAYOUTS_TOKEN` и `DEEPSEEK_API_KEY` уже заданы через окружение, повторного запроса не будет. Дополнительный вариант запуска из каталога решения — `./mrkai`.

Примеры сообщений:

```text
Из Мурманска в Токио в ближайшие две недели, в одну сторону. Покажи самые дешёвые варианты.
```

```text
Хочу из Казани в Сочи в ноябре, туда-обратно на 5–7 дней, до 20000 рублей, прямой рейс.
```

```text
А если разрешить пересадку и увеличить бюджет до 25000?
```

```text
Новая поездка: из Москвы куда угодно по России в декабре, в одну сторону, до 10000 рублей.
```

При месяце без года AI учитывает текущую московскую дату. Для точного запроса явно указывайте год.

## Команды

- `/help` — условия поиска и подсказка.
- `/log` — путь и состояние диагностического файла.
- `/reset`, `/clear` — новый поиск: очистить экран и историю модели.
- `/exit`, `/quit` — выход.

Все команды доступны через автодополнение. Используется общий терминал с Unicode-редактором, историей, многострочным вводом, прокруткой и отменой медленной операции через Esc/Ctrl+C. Повторное нажатие той же клавиши в течение секунды завершает процесс.

## Что поддерживается

Новый самостоятельный запрос с маршрутом начинает новый поиск и не наследует ограничения предыдущей поездки. Если обратный билет не указан, по умолчанию ищется билет в одну сторону. Для «туда-обратно» укажите это явно либо задайте длительность пребывания. Короткие уточнения вроде «в ближайшие 52 дня» сохраняют текущий тип билета. Фраза «в одну сторону» сбрасывает обратную дату, город обратного вылета и длительность поездки.

Можно прилететь в один город, а вернуться из другого: например, Мурманск → Токио и Осака → Мурманск. Агент ищет два отдельных билета и показывает их общую стоимость и две ссылки. Перелёт Токио → Осака не ищется: переезд между городами самостоятельный и не включён в стоимость. Если задана только страна для поездки туда-обратно, города прилёта и обратного вылета подбираются из её предложений. Ограничения дат, общей длительности и бюджета применяются к комбинации билетов.

```text
Найди топ-5 самых дешёвых поездок из Мурманска в Японию в ближайшие 2 месяца, туда-обратно на 1–2 недели. Можно прилететь в Токио и вернуться из Осаки, между городами перееду сам.
```

Для «в Японию туда-обратно» сначала проверяются готовые билеты туда-обратно по стране, затем отдельно до восьми городов из самых дешёвых предложений в одну сторону. Дополнительно подбираются пары отдельных билетов. Пустой кэш обратных отдельных билетов не удаляет готовые варианты. Результаты объединяются, повторы убираются, показываются пять самых дешёвых; для готового билета указана цена за оба направления, для пары — сумма и две ссылки. Это ограниченная выборка кэша, наличие вариантов не гарантируется.

Если ответ пустой, диагностика показывает причины отсева записей: другая длительность поездки, отсутствие обратного билета, даты вне диапазона, бюджет, пересадки или недопустимая ссылка. «Лимит просмотра» означает верхнюю границу, а не число реально полученных билетов.

Один взрослый, эконом, рубли, внутренние и международные направления; билет в одну сторону или туда-обратно; дата, месяц либо диапазон вылета до двух лет; дата/месяц возвращения или длительность поездки; бюджет и фильтр прямых рейсов. Можно искать конкретный город, любые направления в указанной стране или по всему миру. Для «куда угодно по России» сохраняется фильтр РФ. Международные направления используют тот же токен Travelpayouts. Лимит просмотра зависит от количества месяцев и указан в ответе; показывается до пяти самых дешёвых подходящих вариантов из просмотренных.

Источник — **кэш пользовательских поисков Aviasales**, а не поиск наличия в реальном времени. Цена, наличие, багаж и условия проверяются по ссылке. Если подходящих записей нет, это не означает, что билеты отсутствуют. Несколько пассажиров, багаж и сложные маршруты не поддерживаются. Нельзя проверить запрет пересадки в конкретном городе (например, Москве): API возвращает количество пересадок, но не промежуточные аэропорты. Агент должен объяснить это ограничение и уточнить согласие на поиск без такого фильтра, сохранив международное направление. AI может ошибиться при понимании запроса: извлечённые условия выводятся вместе с результатами, их можно уточнить следующим сообщением.

DeepSeek получает запрос и до шести последних обменов с краткими условиями. Цены и ссылки формируются кодом по данным API; модель их не генерирует. Города сопоставляются по названиям из официального справочника; при ошибке распознавания Agent один раз пытается исправить условия. В историю попадают фактические уточнения и ошибки, чтобы последующий вопрос учитывал показанный ответ. Контекст диалога хранится в памяти до выхода или сброса; диагностический журнал сохраняет тексты запросов и ответы на диске. Диагностика показывает этапы и число результатов, без ключей и тел ответов с ошибками. Реальные сообщения вызывают платный API DeepSeek; при старте модель не вызывается.

Необязательные настройки: `DEEPSEEK_MODEL` (по умолчанию `deepseek-chat`), `DEEPSEEK_BASE_URL` (совместимый endpoint; ключ отправляется на указанный адрес). `TRAVELPAYOUTS_BASE_URL` допускает только локальный HTTP-сервер для офлайн-тестов.

## Общая логика и дополнительные интерфейсы

Диагностический журнал включён по умолчанию: `data/trace.jsonl` (или `DATA_DIR/trace.jsonl`). Это JSONL: одна запись на событие с временем, сессией и идентификатором пользовательского запроса. Сохраняются сообщения пользователя, запросы к DeepSeek, успешные ответы модели и Travelpayouts, распознанные условия, исправления плана, причины принятия/отсева билетов и итоговый ответ. Для большого мирового справочника записывается только количество городов. Вместо скрытых рассуждений модели сохраняются краткие объяснения решений программы.

Ключи, авторизационные заголовки, обнаруженные токены и внутренние сетевые адреса маскируются; тела ответов с ошибками не записываются. Журнал содержит тексты запросов и варианты поездок, поэтому хранится с правами 600. Контекст очищается через `/reset`, но диагностический журнал остаётся для разбора. Ротация: 5 МиБ на файл, до трёх файлов (`trace.jsonl`, `.1`, `.2`); крупные события помечаются `truncated`. Команда `/log` показывает путь и сообщает об ошибке записи, если она возникла. Один экземпляр приложения должен использовать отдельный `DATA_DIR`.

Диапазон поиска расширен до двух лет, включая запрос «в ближайшие полгода». Для каждого затронутого месяца запрашивается хотя бы одна страница; бюджет запросов равен максимуму из трёх и числа месяцев, по 100 записей. Фактический лимит выводится вместе с результатом.

При ошибке структуры ответа DeepSeek агент повторно запрашивает исправление, затем собирает максимально подходящий запрос из распознанных полей и сохранённых условий. Обычные уточнения дат, типа билета и недельной поездки восстанавливаются из текста. Ответ показывает применённые условия и предупреждает о нераспознанных ограничениях. Если обязательных данных не хватает, агент показывает известное и задаёт уточнение вместо ошибки формата.

Терминал и Telegram используют **один Agent и один клиент Aviasales**, общие правила проверки и один формат результата. Telegram — отдельный необязательный адаптер, запускаемый через `mrkai --telegram`; для него нужен `TELEGRAM_BOT_TOKEN`. Для обычного `mrkai` этот токен не требуется и не запрашивается.

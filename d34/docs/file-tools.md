# Файловые инструменты проекта

Документ описывает файловые инструменты, которые проект предоставляет через
MCP-сервер. Инструменты реализованы в `files.go` и `mcp.go`.

## Обзор

MCP-сервер запускается командой `--project-mcp-server <root>` и обслуживает
запросы `initialize`, `tools/list` и `tools/call`. Список инструментов
объявляется в функции `serveMCP` (`mcp.go:163`), литерал `tools` начинается
на `mcp.go:166`.

| Инструмент | Назначение | Аргументы | Реализация |
|------------|------------|-----------|------------|
| `git_branch` | Текущая git-ветка проекта | нет | `gitBranch` (`mcp.go:245`) |
| `file_list` | Список файлов проекта | нет | `projectList` (`files.go:52`) |
| `file_read` | Прочитать файл проекта | `path` | `projectRead` (`files.go:88`) |
| `file_search` | Поиск строки по файлам проекта | `query` | `projectSearch` (`files.go:104`) |
| `file_write` | Создать/обновить Markdown в `docs` | `path`, `content` | `projectWrite` (`files.go:138`) |

## Контроль безопасности: `safeProjectFile`

Функция `safeProjectFile(root, name, write)` (`files.go:12`) — общий барьер для
всех файловых операций. Она:

- запрещает пустой и абсолютный путь, а также обратные слэши;
- отклоняет пути вне корня проекта (`.` , `..`, `../…`);
- блокирует сегменты пути, начинающиеся с `.` (скрытые пути);
- прогоняет **каждый** сегмент пути через `safeDocName(part+".md")`, то есть к
  сегменту принудительно дописывается `.md` перед проверкой
  (`files.go:20`–`files.go:24`). Из-за этого для сегментов пути фактически
  действуют только два правила `safeDocName`: запрет ведущей точки и запрет
  «чувствительных» слов. Расширение у сегмента расширением быть не может — оно
  всегда подменяется на `.md`, поэтому правило «расширение не `.md`» на сегменты
  не влияет (оно применяется позже ко всему пути, см. ниже). Именно поэтому
  «чувствительные» имена-сегменты (например, каталог `secret/` или файл
  `docs/secret.md`) отклоняются с ошибкой «скрытый или чувствительный путь» при
  любой операции — и чтении, и записи;
- для чтения разрешает расширения `.md`, `.go`, `.txt` (проверка расширения
  **всего** пути, `files.go:29`–`files.go:32`);
- для записи разрешает только `docs/*.md`: расширение должно быть `.md`, а
  каталог — ровно `docs` (`filepath.Dir(clean) != "docs"`, `files.go:26`–
  `files.go:28`), поэтому вложенные каталоги (`docs/sub/x.md`) для записи
  недоступны;
- запрещает симлинки в цепочке каталогов и «необычные» файлы (не регулярные/симлинки).

## Фильтр имён: `safeDocName`

`safeDocName(name)` (`rag.go:34`) — общий фильтр «безопасного» имени, который
используется и в файловых инструментах, и в RAG-индексе. Имя считается
небезопасным, если:

- начинается с `.` (скрытое), или
- имеет расширение не `.md`, или
- содержит (без учёта регистра) одно из слов: `secret`, `credential`,
  `password`, `token`, `private`, `apikey`, `api_key`.

Важно, что при проверке сегментов пути аргумент формируется как `part+".md"`
(см. выше), поэтому расширение сегмента всегда `.md`; правило про расширение
работает только там, где `safeDocName` вызывается с «настоящим» именем файла —
например, при обходе каталога `docs` в RAG-индексе (`rag.go:110`, `rag.go:115`).
Именно список «чувствительных» слов (а не расширение сегмента) приводит к тому,
что запись в `docs/secret.md` отвергается, даже если это обычный,
не `.`-префиксный путь.

## `file_list` — список файлов

`projectList(ctx, root)` рекурсивно обходит корень проекта через
`filepath.WalkDir`:

- пропускает каталоги с ведущей `.`, а также `data`, `vendor`, `testdata`;
- учитывает только обычные файлы, которые проходят `safeProjectFile(..., false)`;
- ограничивает результат 200 файлами;
- возвращает отсортированный список относительных путей (через `/`);
- прерывается при отмене контекста.

## `file_read` — чтение файла

`projectRead(root, name)`:

- проверяет путь через `safeProjectFile`;
- отклоняет файлы размером более 64 КиБ (`64<<10`, `files.go:97`, ошибка
  «файл слишком велик»);
- возвращает содержимое файла как строку.

## `file_search` — поиск по проекту

`projectSearch(ctx, root, query)`:

- требует длину запроса от 2 до 100 символов (`files.go:105`);
- получает список файлов через `projectList`;
- построчно ищет подстроку без учёта регистра (`strings.Contains` +
  `strings.ToLower`);
- формат результата — `имя:строка: текст`, строки длиннее 240 символов
  обрезаются до 240 символов;
- не более 50 совпадений; при отсутствии совпадений возвращает `Совпадений нет`;
- файлы, которые не удалось прочитать, молча пропускаются.

## `file_write` — запись Markdown

`projectWrite(root, name, content)` (`files.go:138`):

- проверяет путь через `safeProjectFile(..., true)`, то есть запись **только** в
  `docs/*.md` (каталог ровно `docs`, расширение `.md`);
- все правила имени из `safeDocName`, действующие для сегментов (запрет ведущей
  точки и «чувствительных» слов), действуют и здесь: в `docs` нельзя записать
  файл со «чувствительным» словом в имени (`secret`, `token` и т.п.);
- отклоняет содержимое более 64 КиБ (`files.go:144`, ошибка «содержимое слишком
  велико»);
- создаёт каталог `docs` при необходимости (`MkdirAll`, права `0700`,
  `files.go:147`);
- пишет через временный файл `.mrkai-*` (`files.go:151`), права `0600`
  (`files.go:157`), и атомарно заменяет целевой через `os.Rename`
  (`files.go:172`);
- возвращает отчёт: `Сохранён <name>: было N байт, стало M байт`.

Схема аргументов инструмента `file_write` объявляет `path` и `content` как
обязательные (`mcp.go:171`).

## Транспорт MCP

Клиент (`mcpClient` в `mcp.go`) общается с сервером по JSON-RPC 2.0 через
stdin/stdout дочернего процесса, версия протокола — `2025-06-18`. Вызов
инструмента `callTool` требует, чтобы аргументы были JSON-объектом, и ожидает
первый текстовый элемент `content`; при `isError: true` текст трактуется как
сообщение об ошибке.

## Замечания

- Лимиты: 64 КиБ на чтение и запись, 200 файлов в списке, 50 совпадений в поиске.
- Все файловые пути нормализуются (`filepath.Clean`) и проверяются на выход за
  пределы корня проекта.
- Запись возможна исключительно в `docs/*.md` (каталог ровно `docs`); создание
  иных типов файлов инструментом `file_write` невозможно.
- Дополнительно блокируются имена-сегменты с «чувствительными» словами (через
  `safeDocName(part+".md")`), поэтому некоторые пути внутри `docs/`, например
  `docs/secret.md`, тоже недоступны для записи.

# День 34 — ассистент для файлов проекта

Терминальный `mrkai` выполняет задачи на уровне цели. `/task` даёт модели MCP инструменты для списка файлов, чтения, поиска по нескольким файлам и записи Markdown документации. Сценарии: найти использования API в коде и обновить `docs/` на основе нескольких исходников. Созданные файлы остаются на диске; результат воспроизводится повторным запросом и просмотром сохранённого файла.

## Запуск

Из `d34`: `export PATH="$PWD:$PATH"`, задайте `DEEPSEEK_API_KEY` через окружение и выполните `mrkai`. Для другого проекта задайте `MRKAI_PROJECT_ROOT`. Примеры целей: `/task Оцени, какие части проекта затронет изменение файлового поиска, и обоснуй выводы источниками` и `/task Подготовь и сохрани памятку для нового разработчика о файловых возможностях ассистента и их ограничениях на основе текущей реализации`. Агент сам выбирает исходные файлы, инструменты и документ для сохранения.

Также доступны `/help ВОПРОС`, `/index build`, `/index status`, `/mcp tools`, `/mcp git branch`, `/reset`, `/clear`, `/exit`, `/quit`. Обычный текст — многоходовой чат. Файловые инструменты читают только обычные `.md`, `.go`, `.txt` без скрытых и чувствительных имён; запись ограничена `docs/*.md`.

Проверка без API: `go test ./...` и `go vet ./...`.

На одну задачу доступны до 32 шагов модели с инструментами и до 128 вызовов инструментов. После исчерпания бюджета агент получает отдельный запрос без инструментов, чтобы сообщить выполненные действия и оставшуюся работу. Диагностика показывает расход бюджета.

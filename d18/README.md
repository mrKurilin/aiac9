# День 18 — планировщик и фоновые задачи

MrKai запускает локальный MCP-сервер `mrkScheduler` вместе с терминальным агентом. Инструмент создаёт разовые и периодические напоминания, сохраняет их в JSON и выдаёт агрегированную сводку. При срабатывании терминал показывает только текст напоминания или список открытых MR. Ход запросов и счётчики запусков автоматически не печатаются; подробная статистика доступна по команде `/mcp mrkscheduler summary`. Если агент отвечает на сообщение, результат появится после завершения ответа. Расписание работает, пока запущен `mrkai`. После перезапуска просроченное задание выполняется один раз, затем период отсчитывается заново.

По умолчанию сообщения обрабатываются как обычный чат: агент помнит недавний диалог, не определяет `task_ready` и не создаёт цель задачи. Команда `/plan-mode enable` включает уточнение задачи и сохранение цели; `/plan-mode disable` возвращает обычный чат. Режим после перезапуска снова выключен, даже если ранее была сохранена задача. Для продолжения такой задачи включите режим и выполните `/resume`, если задача была на паузе. Сохранены инварианты и GitLab MCP из предыдущего дня. На каждом ходе агент получает схемы инструментов обоих MCP-серверов и предлагает их модели. Модель сама решает, нужен ли вызов, а результат возвращается ей перед ответом. Текст ответа выводится по мере поступления фрагментов SSE, в том числе после вызова MCP-инструмента. Для прямых команд `/mcp` ключ модели не требуется; для запросов на естественном языке задайте `DEEPSEEK_API_KEY`. Для регулярного сбора MR задайте `GITLAB_API_TOKEN`; для собственного GitLab используйте `GITLAB_API_URL`.

## Установка и запуск

Нужен Go 1.21+. В каталоге этого дня запускайте агент сразу:

~~~sh
./mrkai
~~~

Если нужен запуск командой `mrkai` без `./`, добавьте текущий каталог в `PATH`:

~~~sh
export PATH="$PWD:$PATH"
mrkai
~~~

Исполняемый файл `./mrkai` собирает и запускает Go-программу автоматически. Для постоянной работы оставьте процесс запущенным в терминале или управляйте им штатным менеджером процессов вашей системы. Данные по умолчанию находятся в `./data/reminders.json`; каталог можно изменить через `DATA_DIR`. Файл создаётся с правами только для текущего пользователя. Токены задаются переменными окружения и в JSON расписания не записываются.

## Команды

- `/mcp mrkscheduler` — инструменты планировщика;
- `/mcp mrkscheduler add 60 0 Проверить отчёт` — разовое напоминание через 60 секунд;
- `/mcp mrkscheduler add 10 3600 Подвести итоги` — первое срабатывание через 10 секунд, затем каждый час;
- `/mcp mrkscheduler mrs 30` — каждые 30 секунд получать открытые MR из моих проектов;
- `/mcp mrkscheduler mrs 30 group/project` — то же для одного проекта;
- `/mcp mrkscheduler list` — задания и время следующего запуска;
- `/mcp mrkscheduler summary` — число срабатываний и последние 100 событий;
- `/mcp mrkscheduler cancel R1` — остановить задание;
- `/mcp mrkgitlab mrs` — открытые MR пользователя;
- `/plan-mode enable` — включить цель задачи и уточняющие вопросы;
- `/plan-mode disable` — вернуться к обычному чату;
- `/state`, `/invariants`, `/invariant add`, `/invariant remove`, `/invariant clear`, `/pause`, `/resume`, `/reset`, `/info`, `/exit` — сохранённые команды агента.

Задержка задаётся в секундах от 1 до 31536000. Период `0` означает однократное выполнение; для повторения допустим период от 10 секунд. Все команды доступны через автодополнение. Можно написать обычным текстом: «Выводи открытые МРы каждые 30 секунд». При настроенном `DEEPSEEK_API_KEY` модель выберет MCP-инструмент и создаст расписание; без ключа используйте `/mcp mrkscheduler mrs 30`. По расписанию агент покажет число открытых MR, названия, авторов, ссылки и краткие статусы. Если агент отвечает на другое сообщение, фоновый вывод появится после его ответа. Одинаковая сводка MR два раза подряд не печатается; после другого сообщения она может появиться снова. `/reset` останавливает все активные задания и очищает контекст; одно задание можно остановить командой `/mcp mrkscheduler cancel ID`. История запусков остаётся в JSON. За один ответ допускается до восьми последовательных раундов вызовов инструментов; при превышении агент сообщает об ошибке.

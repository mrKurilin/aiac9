# День 17 — результат

## Реализация

MrKai запускает собственный MCP-сервер `mrkGitlab` по stdio. Сервер оборачивает GitLab REST API и регистрирует инструмент `list_open_merge_requests`: он доступен через `tools/list` и вызывается через `tools/call`. Входной параметр описан JSON-схемой: необязательный `project_id` — числовой ID или путь `group/project`. Без параметра сервер получает проекты, где пользователь участник (`/projects?membership=true&archived=false`), и открытые MR каждого из них (`state=opened`) с сохранением пагинации. Результат возвращается как `content` с JSON: ID проекта, номер, полная ссылка, название, автор, URL и краткая сводка по статусу MR. Ошибки возвращаются через `isError` без тела ответа GitLab.

Агент использует инструмент через модель. Список из `tools/list` передаётся в DeepSeek как `tools`; модель сама решает вызвать `list_open_merge_requests` и выбирает аргументы. Агент выполняет вызов через MCP-клиент, возвращает результат модели сообщением `tool`, и модель формирует ответ по полученным данным — например, какой MR ближе всего к мержу. Цикл допускает до трёх раундов вызовов. Если модель в этом же ходе создаёт задачу, агент сразу продолжает и возвращает список MR без дополнительного запроса. В историю диалога сохраняются только вопрос и финальный ответ.

Во время хода терминал показывает вызов `Агент вызывает mrkGitlab.list_open_merge_requests {...}`, живые notifications сервера (приём вызова, проверка авторизации, HTTP-статус страниц, количество MR, завершение) и передачу результата модели. Для ручной проверки остаются команды `/mcp`, `/mcp mrkgitlab`, `/mcp mrkgitlab mrs [group/project]` и `/mcp mrkgitlab call NAME JSON`.

Авторизация REST API использует `GITLAB_API_TOKEN` в `Authorization: Bearer`, для собственного GitLab есть `GITLAB_API_URL`. Один Ctrl+C или Esc отменяет активный вызов вместе с HTTP-запросом; MCP-клиент остаётся пригодным для следующего вызова.

## Сценарий видео

1. Показать в `gitlab_server.go` регистрацию инструмента, JSON-схему параметров и запрос к REST API.
2. Показать в `agent_tools.go` передачу инструментов модели и цикл вызова.
3. Запустить `mrkai` с `GITLAB_API_TOKEN` и `DEEPSEEK_API_KEY`, выполнить `/mcp mrkgitlab`.
4. Спросить: «какие у меня открытые MR и какой из них ближе всего к мержу?» — показать вызов инструмента агентом, прогресс сервера и ответ модели по полученным MR.

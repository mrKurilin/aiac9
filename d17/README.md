# День 17 — самописные MCP-серверы

MrKai запускает один локальный MCP-сервер `mrkGitlab` по stdio. Он предоставляет инструмент `list_open_merge_requests`: сводку по открытым MR во всех ваших проектах или в указанном проекте, со ссылками.

Сервер регистрирует инструмент через `tools/list` и вызывается через `tools/call`. Для просмотра MCP-сервера используйте `/mcp`.

Агент подключает инструменты MCP к модели: список из `tools/list` передаётся в DeepSeek как `tools`. Модель сама решает вызвать `list_open_merge_requests`, агент выполняет вызов через MCP-клиент, возвращает результат модели сообщением `tool`, и модель отвечает по полученным данным. В историю диалога сохраняются только вопрос и финальный ответ.

## Запуск

Нужен Go 1.21+. На этой машине `mrkai` уже доступен из любой директории:

~~~sh
mrkai
~~~

Для GitLab задайте персональный токен с доступом к нужному проекту:

~~~sh
export GITLAB_API_TOKEN="<ваш-токен>"
mrkai
~~~

По умолчанию используется `https://gitlab.com/api/v4`. Для собственного экземпляра задайте `GITLAB_API_URL` с адресом его REST API по HTTPS. Токен не сохраняется в проекте. Для диалога с агентом, в том числе с вызовом MCP-инструмента моделью, нужен `DEEPSEEK_API_KEY`; для команд `/mcp` он не нужен.

## Команды

- `/mcp` — список доступных MCP-серверов;
- `/mcp mrkgitlab` — инструменты mrkGitlab;
- `/mcp mrkgitlab mrs` — открытые MR во всех проектах, где вы участник, со ссылками и краткой сводкой;
- `/mcp mrkgitlab mrs group/project` — открытые MR проекта;
- `/mcp mrkgitlab call list_open_merge_requests {"project_id":"group/project"}` — прямой вызов инструмента GitLab MCP;
- `/info` — остальные команды.

GitLab API принимает также числовой `project_id`. Без проекта сервер получает список ваших проектов (`/projects?membership=true&archived=false`) и запрашивает открытые MR каждого из них (`state=opened`), поэтому публичные MR чужих проектов не попадают в ответ. Авторизация отправляется как `Authorization: Bearer`, что подходит для персональных и OAuth-токенов. Ответ содержит ID проекта, номер MR в проекте (`iid`), полную ссылку вида `group/project!iid`, название, автора, URL и краткую сводку: черновик или готов к ревью, ветки, статус слияния, число комментариев, дату обновления и первую строку описания. При ошибке API тело ответа сервера не выводится.

Во время запроса GitLab MCP выводит диагностические события: приём вызова, проверку авторизации, номер страницы, HTTP-статус, количество MR, завершение, таймаут или отмену. Таймаут одного HTTP-запроса — 15 секунд. Логи не содержат токен и тело ответа с ошибкой.

Автодополнение показывает команды по одному уровню: после `/` видны `/info` и `/mcp`, после `/mcp` — только непосредственные варианты, а после `/mcp mrkgitlab` — действия mrkGitlab. Остальные команды появляются при вводе их начальных букв. Стрелки вверх и вниз перемещают выбор по текущему списку; Tab подставляет выбранную команду, Enter выполняет готовую команду.

Один Ctrl+C или Esc останавливает текущий вызов, включая HTTP-запрос через GitLab MCP. Повторное нажатие той же клавиши в течение секунды завершает `mrkai`.

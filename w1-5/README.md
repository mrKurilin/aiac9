# w1-5 · LLM Playground (DeepSeek + OpenAI) — версии моделей

Один и тот же запрос выполняется через API на **слабой**, **средней** и **сильной** модели двух провайдеров (DeepSeek и OpenAI). Для каждого ответа замеряются **время**, **число токенов** и **стоимость**; рядом виден сам ответ — можно сравнить качество. Цель — пощупать, как отличаются модели, и понять, какую брать под задачу.

## Запуск

```bash
export DEEPSEEK_API_KEY=sk-...
export OPENAI_API_KEY=sk-...
go run .
```

Откройте http://localhost:8080

Оба ключа необязательны: если какого-то нет, колонка соответствующего провайдера покажет ошибку.

## Колонки по умолчанию

| Колонка | Провайдер | Модель | Ставка $/1M (вх/вых) | Идея |
|---------|-----------|--------|----------------------|------|
| Слабая  | OpenAI    | `gpt-5.6-luna`     | 0.20 / 1.20 | младший класс — быстрый и дешёвый |
| Средняя | DeepSeek  | `deepseek-chat`     | 0.27 / 1.10 | открытая main-stream модель, часто дешевле «слабой» у конкурентов |
| Сильная | OpenAI    | `gpt-5.6-sol`       | 4.00 / 20.00 | флагман — сильнее на сложных задачах, но дороже и медленнее |

Модель, провайдера и цену за 1M токенов можно менять прямо в шапке колонки. При выборе известной модели цена подставляется автоматически; если у модели нет записи в справочнике — впишите актуальную цену вручную. Если модель вернёт ошибку «model not found», проверьте актуальные id по ссылкам ниже.

## Что сравнивать

- **Качество ответа** — ответы рендерятся как Markdown в трёх колонках; на сложном/аналитическом промпте разница заметна лучше всего.
- **Время** — замеряется от клиента (секундомер крутится, пока модель думает), показывается на прогон и среднее в шапке колонки.
- **Токены** — входные/выходные/всего из usage API плюс скорость в ток/с.
- **Стоимость** — считается как вход × ставка входа + выход × ставка выхода по редактируемым ценам колонок (ориентир без кэша и скидок).
- **Ресурсоёмкость** — у hosted-API напрямую не измерить; косвенные признаки: время ответа, число выходных токенов и цена. В поле «Ваш вывод» на странице удобно зафиксировать наблюдения для отчёта.

## API сервера

- `GET /` — веб-интерфейс
- `POST /api/complete` — тело `{"provider": "deepseek"|"openai", "model": "...", "prompt": "...", "max_tokens": 2000, "params": {...}}`; `params` — произвольные доп. параметры запроса (для DeepSeek идут в OpenAI-совместимый body, для OpenAI — в Responses API body); ответ `{"content": "...", "finish_reason": "...", "prompt_tokens": N, "completion_tokens": N, "total_tokens": N}` или `{"error": "..."}`

## Структура

- `main.go` — HTTP-сервер и прокси к DeepSeek (`/chat/completions`) и OpenAI (`/v1/responses`)
- `index.html` — веб-интерфейс (встроен через `go:embed`); KaTeX подключён с CDN

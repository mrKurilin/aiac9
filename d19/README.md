# День 19 — композиция MCP-инструментов

Терминальный агент MrKai получил MCP-сервер `mrkPipeline`. Он ищет текст в локальных документах, готовит краткую выдержку и сохраняет отчёт. `run_pipeline` автоматически вызывает эти три шага в одном порядке. Отдельные инструменты `search`, `summarize` и `save_to_file` тоже доступны модели и через прямую команду. Сохранены чат, GitLab MCP, планировщик и команды управления задачей из предыдущего дня. По умолчанию работает обычный чат без этапов и планирования; режим задачи включается только командой `/plan-mode enable`.

## Установка и запуск

Нужен Go 1.21+. Из каталога `aiac9/d19` добавьте текущий каталог в `PATH` и запустите агент:

~~~sh
export PATH="$PWD:$PATH"
mrkai
~~~

Файл `mrkai` собирает и запускает программу. Работает и `./mrkai`. Для прямых MCP-команд ключ модели не нужен. Для запросов на естественном языке задайте `DEEPSEEK_API_KEY`; можно также задать `DEEPSEEK_BASE_URL` и `DEEPSEEK_MODEL`. Для GitLab используйте `GITLAB_API_TOKEN` и при необходимости `GITLAB_API_URL`.

Документы для поиска лежат в `./knowledge` (`.md` и `.txt`, файлы до 64 КиБ); путь можно изменить через `KNOWLEDGE_DIR`. Отчёты сохраняются в `./data/reports`; базовый каталог меняется через `DATA_DIR`. Имя отчёта должно быть простым именем файла `.md`. Отчёт с таким именем заменяется при повторном запуске.

## Команды

- `/mcp mrkpipeline` — список инструментов;
- `/mcp mrkpipeline run MCP | mcp-report.md` — выполнить поиск, обработку и сохранение;
- `/mcp mrkpipeline call search {"query":"MCP"}` — вызвать отдельный инструмент; аналогично доступны `summarize` и `save_to_file`;
- `/mcp mrkgitlab mrs` — открытые MR;
- `/mcp mrkscheduler` — инструменты планировщика;
- `/plan-mode enable`, `/plan-mode disable`, `/state`, `/invariants`, `/invariant add`, `/invariant remove`, `/invariant clear`, `/pause`, `/resume`, `/reset`, `/info`, `/exit` — команды агента.

Все команды и подкоманды доступны через автодополнение. При настроенном `DEEPSEEK_API_KEY` просто напишите: «Найди материалы про MCP, составь выдержку и сохрани в mcp-report.md». Модель получает схемы MCP-инструментов, вызывает `run_pipeline` и отвечает после сохранения отчёта. Прямая команда `/mcp mrkpipeline run` работает без ключа. Без совпадений цепочка завершится ошибкой до создания отчёта. Обработка текста здесь простая: используются первые три непустые строки найденных документов, а не LLM-суммаризация.

# День 30 — модель на VPS с HTTP API

В `server/` находятся HTTP API, Dockerfile и установщик модели на VPS. В `client/` находится терминальный `mrkai`. API хранит контекст отдельных диалогов в памяти и поддерживает сброс. Пользователи подключаются напрямую по публичному IP-адресу и общему паролю API.

## Локальный запуск модели и сервиса

Нужны Go 1.21+, Ollama и локальная `qwen3:4b-instruct`. Из каталога `aiac9/d30/client`:

```sh
cd aiac9/d30/client
chmod +x mrkai
export PATH="$PWD:$PATH"
mrkai
```

В терминале агента запустите `/server start`, затем `/server check`. Последняя команда выполнит три коротких HTTP-запроса через тот же API. Сервис останавливается по `/server stop` или при выходе из агента. Для длительной работы процесс `mrkai` должен оставаться запущенным.

## Требования к VPS

Для проверки задания с моделью `qwen3:4b-instruct` на CPU выбирайте виртуальную машину не меньше **4 vCPU, 8 ГБ RAM и 30 ГБ SSD**. Это практический ориентир для одного запроса к модели за раз, а не гарантия скорости: на разделяемых vCPU ответ может идти медленно. Сам файл модели занимает около 2,5 ГБ; место также нужно для ОС, Docker-образов, сборки и кэша. GPU не требуется и текущим скриптом не подключается.

- **ОС:** Ubuntu 24.04 LTS или Debian 12 с `apt` и `systemd`; архитектура `x86_64` либо `aarch64`.
- **Доступ:** пользователь с `sudo` или root для установки Docker; полный checkout `aiac9` на VPS. Go на VPS отдельно ставить не нужно.
- **Сеть:** публичный IPv4-адрес; входящий TCP-порт **8780** открыт в панели провайдера и локальном файрволе VPS. Для администрирования нужен SSH или консоль провайдера. Порт Ollama **11434** наружу открывать не нужно.
- **Загрузка:** исходящий доступ в интернет и работающий DNS для установки пакетов, Docker-образов и модели. Во время установки скачиваются несколько гигабайт данных.

## Установка на VPS

На VPS с указанными ресурсами откройте полный checkout репозитория `aiac9` с веткой `d30`. Из каталога `aiac9/d30/server` задайте пароль длиной от 16 символов и запустите установку:

```sh
cd aiac9/d30/server
printf 'Пароль API: '
read -r -s SERVICE_API_TOKEN
printf '\n'
export SERVICE_API_TOKEN
sudo --preserve-env=SERVICE_API_TOKEN ./install-vps.sh
```

Скрипт устанавливает Docker из репозитория дистрибутива, собирает API из исходников, запускает Ollama и загружает модель.

API слушает `0.0.0.0:8780`; Ollama доступна только внутри VPS на `127.0.0.1:11434`. Публичный адрес API — `http://PUBLIC_IP:8780`, где `PUBLIC_IP` нужно заменить публичным IP-адресом VPS. Пароль передаётся в заголовке `Authorization: Bearer ...`; скрипт не сохраняет его в репозитории. HTTP не шифрует пароль и текст диалога: их может увидеть тот, кто имеет доступ к сетевому трафику между клиентом и сервером.

После установки контейнеры `aiac9-d30-api` и `aiac9-d30-ollama` запускаются после reboot. Состояние можно проверить командами `sudo docker ps` и `sudo docker logs aiac9-d30-api`. Повторный запуск скрипта пересобирает API и сохраняет загруженную модель в Docker volume.

### Логи диалогов на VPS

После установки версии с логированием смотрите новые запросы, ответы и сбросы диалога в терминале VPS:

```sh
sudo docker logs -f --tail 100 aiac9-d30-api
```

Каждая запись — отдельная строка JSON с временем, событием (`chat request`, `chat response` или `chat reset`) и ID сессии. Для запроса и успешного ответа записывается текст сообщения; для ответа также записываются HTTP-статус и длительность. Заголовок `Authorization` в журнал не пишется. Прошлые диалоги, обработанные до обновления сервиса, восстановить из этих логов нельзя.

Чтобы включить логи на уже работающей VPS, обновите код и повторно запустите `install-vps.sh` с тем же `SERVICE_API_TOKEN`, как в разделе выше. Скрипт пересоздаст только контейнер API и сохранит загруженную модель. Docker хранит до трёх файлов журнала API по 10 МБ каждый. Тексты диалогов будут доступны администраторам VPS через Docker, поэтому не отправляйте в чат данные, которые не хотите хранить на сервере.

## Локальный клиент для модели на VPS

На локальном компьютере, из каталога `aiac9/d30/client` того же checkout, задайте публичный адрес и тот же пароль, который указали на VPS:

```sh
cd aiac9/d30/client
export MRKAI_API_URL=http://PUBLIC_IP:8780
printf 'Пароль API: '
read -r -s MRKAI_API_TOKEN
printf '\n'
export MRKAI_API_TOKEN
./mrkai
```

Нужен один локальный терминал. Обычный текст отправляется модели на VPS. `/reset` и `/clear` очищают текущий диалог и на сервере, и в терминале. Каждый запуск `mrkai` создаёт отдельную сессию. Все, кому вы сообщите адрес и пароль, смогут подключиться со своего устройства. Если `MRKAI_API_URL` не задан, `mrkai` работает с локальной Ollama как прежде.

Для проверки задания на арендованной VPS отправьте в локальном `mrkai` два последовательных вопроса. Во втором спросите о факте из первого: ответ должен учитывать историю. Выполните `/reset`, затем повторите вопрос о прежнем факте: новый диалог не должен его знать. На VPS `sudo docker ps` должен показывать два контейнера в состоянии `Up`. При первом вопросе модель может загружаться дольше последующих.

## HTTP API

- `GET /health` — статус HTTP-сервиса и имя модели.
- `POST /v1/chat` с телом `{"session_id":"session-0123456789abcdef","message":"Привет"}` — ответ и сохранение контекста этой сессии.
- `POST /v1/reset` с телом `{"session_id":"session-0123456789abcdef"}` — очистка сессии.

Существующий вариант `POST /v1/chat` с массивом `messages` также работает без хранения истории. Ответ содержит `message`, число токенов и длительность. При включённой авторизации передайте токен в заголовке `Authorization: Bearer ...`. Не помещайте токен в репозиторий.

## Ограничения ресурсов

- Одна генерация за раз; другие одновременные запросы получают HTTP 429.
- Не более 12 запросов в минуту на весь сервис.
- В памяти не более 64 сессий; неактивные сессии удаляются через час, при рестарте сервиса история теряется.
- Контекст сессии сокращается до последних 12 сообщений и 12 000 символов; одно входящее сообщение не длиннее 12 000 символов.
- Контекст Ollama — 4096 токенов; ответ — до 256 токенов.
- Размер HTTP-тела — до 16 КиБ; ожидание модели — до трёх минут.

Скрипт запускает Ollama на CPU; подключение GPU к контейнеру не настроено. Реальное сетевое развёртывание и проверка с другого устройства ещё не выполнялись.

## Команды клиента

- При работе с VPS: `/model status`, `/reset`, `/clear`, `/help`, `/exit`, `/quit`.
- При работе с локальной Ollama дополнительно доступны `/server start|status|check|stop`, `/index build [КАТАЛОГ]`, `/index status`, `/profile status|baseline|optimized` и `/benchmark ВОПРОС`.

# Архитектура ревью

Команда `/review` собирает список изменённых файлов и diff через git. Локальный RAG индексирует README, Markdown документацию и Go исходники. Агент передаёт модели diff и найденные фрагменты и проверяет JSON ответа: `decision` и Markdown в `body`.

Решения: `approve` — существенных проблем нет; `request_changes` — конкретная проблема требует исправления до слияния; `comment` — необязательные рекомендации или недостаточно данных. Пустой текст, неизвестное решение или неверный JSON останавливают публикацию. При обрезанном diff автоматический approve заменяется на comment.

Workflow получает JSON через `--review-json`, затем `scripts/publish_review.py` отправляет формальное GitHub review (`APPROVE`, `REQUEST_CHANGES`, `COMMENT`) с `commit_id` проверенной ревизии. Ошибка API завершает шаг с ошибкой. Ревью из терминала только показывает решение и текст и не обращается к GitHub.

# День 32 — автоматическое ревью PR

`mrkai` — терминальный агент с обычным многоходовым чатом и явно включаемым ревью. Команда `/review BASE HEAD` получает список изменённых файлов и diff от общей базы веток, ищет контекст в документации и Go-коде, затем возвращает потенциальные баги, архитектурные проблемы и рекомендации.

## Установка и запуск

Нужен Go 1.21+ и ключ DeepSeek-совместимого API. Из `aiac9/d32`:

```sh
export PATH="$PWD:$PATH"
export DEEPSEEK_API_KEY=YOUR_API_KEY
mrkai
```

`MRKAI_PROJECT_ROOT` задаёт абсолютный путь к проверяемому проекту; по умолчанию используется каталог d32. `DEEPSEEK_BASE_URL` задаёт URL chat completions (по умолчанию `https://api.deepseek.com/chat/completions`), `DEEPSEEK_MODEL` — модель (по умолчанию `deepseek-chat`). Ключ задаётся только через окружение.

## Команды

- `/review BASE HEAD` — ревью изменений PR между общей базой веток и HEAD.
- `/index build`, `/index status` — построить локальный индекс или показать число фрагментов.
- `/help` — подсказка.
- `/reset`, `/clear` — очистить диалог и экран, сохранив индексы и документы.
- `/exit`, `/quit` — выйти.

Команды и подкоманды доступны через автодополнение. Общий терминал поддерживает Unicode, историю, многострочный ввод, прокрутку и отмену медленных операций.

## Автоматическое ревью

Workflow `.github/workflows/day32-review.yml` запускается при создании и обновлении PR, проверяет весь репозиторий и публикует формальное GitHub review: **Approve**, **Request changes** или **Comment**. Текст ревью сохраняется в Markdown; review привязан к SHA проверенного коммита. Он требует секрет GitHub Actions `DEEPSEEK_API_KEY`; PR из форков пропускаются. Для автоматического Approve включите **Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests**. Право `pull-requests: write` уже задано в workflow.

`approve` означает отсутствие существенных проблем при достаточном контексте; `request_changes` — конкретную проблему, которую нужно исправить до слияния; `comment` — необязательные рекомендации или недостаток данных. Ошибочный JSON модели останавливает workflow; обрезанный diff не получает автоматического approve.

Режим для пайплайна использует тот же Agent:

```sh
mrkai --review-json BASE HEAD
```

Он выводит JSON с полями `decision` и `body`. `mrkai --review BASE HEAD` и терминальная команда `/review BASE HEAD` показывают решение и Markdown локально, без публикации в GitHub.

При запуске проверяется, что `MRKAI_PROJECT_ROOT` указывает на существующий каталог. Diff ограничен 80 КБ и обрезается на границе UTF-8 символа. RAG использует локальный лексический поиск по именам файлов и содержимому diff: до трёх фрагментов документации и трёх фрагментов кода. Индексируются до 100 Markdown-файлов и 100 Go-файлов размером до 1 МБ; изменённые файлы имеют приоритет. Отдельный `docs/` не обязателен. Скрытые файлы, ссылки, каталоги данных и файлы с секретными именами исключаются. Локальное ревью использует контекст текущего рабочего дерева; для соответствия HEAD запустите его из checkout этой ревизии, как делает workflow.

RAG для каждого ревью перестраивается по текущему рабочему дереву, чтобы не использовать устаревший контекст PR. Это обход дерева и чтение до 200 файлов на запуск; для больших проектов возможна заметная задержка. Индекс ревью сохраняется в `data/review-index.json` внутри проверяемого проекта. `/index build` и `/index status` управляют отдельным `data/index.json` в каталоге d32; ревью этот индекс не использует. Оба индекса остаются после `/reset` и `/clear`. Между запусками GitHub Actions кэш индекса не настроен.

Перед получением diff ревью исключает пути с секретными именами (`secret.txt`, `secret/`, `secrets/`, `.env*`, ключи и файлы учётных данных). Их содержимое не читается для diff и не передаётся модели. Если есть исключённые файлы, автоматический approve всего PR недоступен: решение approve заменяется на comment. Если исключены все файлы, модель не вызывается, публикуется поясняющее review Comment. Это фильтр известных секретных путей; он не определяет произвольные секреты в обычном исходном файле.

Для PR RAG использует только файлы, отслеживаемые Git: локальные неотслеживаемые отчёты ревью не попадают в prompt. Суммарный размер текста сообщений модели ограничен 100 КБ, обрезка сохраняет UTF-8; при сокращении контекста автоматический approve запрещён. Ошибка проверки состояния индексируемого файла завершает операцию, а не скрывается. Workflow перед вызовом API запускает Go-тесты и vet, Python-тесты публикации, PTY smoke и регрессионные тесты терминала — без платных запросов.

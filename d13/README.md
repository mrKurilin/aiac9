# День 13 — конечный автомат состояния задачи

MrKai ведёт одну задачу через формальные этапы:

~~~text
planning → execution → validation → done
              ↘ planning    ↘ execution
~~~

Состояние содержит цель, этап, текущий шаг, ожидаемое действие, завершённые
шаги и последние сообщения диалога. Модель предлагает обновление состояния в
структурированном ответе, а Go-код автоматически применяет только разрешённый
переход.
Команды `/pause` и `/resume` сохраняют и восстанавливают задачу целиком, поэтому
после перезапуска не нужно заново объяснять цель и уже выполненную работу.

Во время ответа модели терминал продолжает читать ввод. Новые сообщения
помещаются в очередь и затем обрабатываются по порядку с актуальным состоянием.
Задачу тоже не нужно создавать командой: обычный запрос автоматически открывает
`planning`, когда цель понятна. Сразу после строки
`Задача создана автоматически · этап: planning` запускается отдельный
потоковый запрос на составление плана — дополнительное сообщение или
предварительное одобрение пользователя не требуется. Если формулировка
неоднозначна, агент сначала задаёт один уточняющий вопрос. Утверждение готового
плана требуется только для перехода к `execution`.

В этом дне намеренно нет веб-интерфейса, профилей, погоды, статей и общей
долговременной памяти: оставлены только LLM-клиент и компоненты, необходимые для
Task State Machine.

## Установка и запуск

Нужны Go 1.21+ и ключ DeepSeek в окружении.

~~~sh
cd aiac9/d13
chmod +x mrkai
mkdir -p "$HOME/.local/bin"
ln -sf "$PWD/mrkai" "$HOME/.local/bin/mrkai"
export PATH="$HOME/.local/bin:$PATH"
export DEEPSEEK_API_KEY="<ваш-ключ>"
mrkai
~~~

Из каталога дня также доступен запуск `./mrkai`. Основной интерфейс всегда
терминальный; аргументы и demo-режимы не нужны.

## Рабочий цикл

~~~text
Реализуй сервис авторизации на Go с JWT
Составь план из четырёх шагов
Добавь к плану проверку срока действия токена
План подходит, утверждаю
Реализация готова, можно проверять
/pause продолжу завтра
/exit
~~~

После нового запуска:

~~~text
/resume
Продолжай
Все проверки успешны
~~~

Этапы и шаги обновляются автоматически. Переход из `planning` в `execution`
разрешается только после явного утверждения плана. Просьба «пропусти план и
сразу пиши код» выводит уведомление `переход planning → execution запрещён` и
не вызывает модель. Другие попытки перепрыгнуть граф переходов также
отклоняются программно.

После разрешённого перехода в `execution` сразу запускается отдельный потоковый
проход реализации. Агент получает инструкцию выполнить весь утверждённый план
последовательно без подтверждения каждого шага. Он обращается к пользователю
только если без недостающих данных продолжить невозможно; завершённая
реализация переводится к предложению этапа `validation`.

Подтвердить готовый план можно полной фразой (`План утверждаю`, `План
согласован`) или короткой самостоятельной репликой: `всё ок`, `согласовано`,
`утверждено`, `приступай`. Реплика с продолжением вроде «всё ок, но добавь…»
считается правкой, а не окончательным утверждением.

Явные команды перехода имеют приоритет над ошибочным предложением модели:
например, `Переходим к валидации`, `Перейди к проверке`, `Переходим к
реализации` или `Вернись к планированию`. Целевой этап всё равно проверяется по
разрешённому графу, поэтому недопустимый переход не будет выполнен.

## Команды

~~~text
/state
/pause [ПРИЧИНА]
/resume
/reset
/info
/exit
~~~

`/state` показывает формальное состояние без обращения к модели. Пока модель
обрабатывает запрос, можно вводить следующие сообщения: терминал подтвердит
постановку в очередь и сохранит порядок ввода.
В интерактивном режиме `/reset` очищает ленту чата вместе с задачей и её
сохранённым контекстом; после команды остаётся только подтверждение сброса.

## Интерфейс терминала

В интерактивном терминале две нижние строки закреплены и не прокручиваются:

~~~text
Состояние: рассуждает  ·  Этап: planning
→ текст сообщения
~~~

Во время запроса отображается состояние `рассуждает` и анимированный спиннер;
пока он движется, ответ ещё формируется. После полного ответа спиннер исчезает,
а состояние возвращается к `активна`, `пауза` или `завершена`.

Строка ввода не содержит подписи «Вы». Поддерживаются:

- `Enter` — отправить сообщение;
- правый `Enter` на цифровом блоке — также отправить сообщение;
- `Shift+Enter` — вставить новую строку без отправки;
- `←` и `→`, `Home` и `End` — перемещаться по набранному тексту;
- `Alt+←`/`Alt+→` или `Ctrl+←`/`Ctrl+→` — переходить по словам;
- `↑` и `↓` — перемещаться между строками; из пустого или однострочного поля
  `↑` возвращает ранее отправленные сообщения, повторные нажатия листают
  историю, а `↓` возвращает вперёд к сохранённому черновику;
- колесо мыши — прокручивать ленту чата; оно не переключает историю ввода;
- `Alt+S` — включить или выключить режим обычного выделения текста мышью;
- `Backspace` — удалить символ;
- `Delete` — удалить следующий символ;
- `Alt+Delete` или `Alt+Backspace` — удалить предыдущее слово;
- `Ctrl+W` — альтернативное удаление предыдущего слова;
- `Ctrl+U` — очистить строку.
- `Ctrl+C` — остановить активный запрос, восстановить терминал и выйти.

Когда агент закончил отвечать, в пустом поле серым показывается предлагаемая
следующая реплика и пометка `[Tab]`. Нажатие `Tab` переносит предложение в поле:
его можно отредактировать и отправить обычным `Enter`. Во время ответа подсказка
скрыта, чтобы не конкурировать с активным спиннером. Для этапов это, например,
`План утверждаю`, `Продолжай реализацию по плану` и `Покажи результаты проверки`.

Многострочный composer растёт вверх до шести строк и всегда оставляет текущую
позицию курсора видимой. В терминалах без различимых модификаторов `Ctrl+J`
доступен как дополнительный способ вставить новую строку.

Ответы и уведомления отображаются над закреплённым полем. Экран строится заново
из внутреннего буфера, поэтому ввод не дублируется в истории при каждом
нажатии. В неинтерактивном режиме, например при pipe, используется обычный
построчный ввод с prompt `→`.

В полноэкранном режиме приложение включает mouse reporting для колеса. Для
быстрого выделения можно удерживать `Shift` при перетаскивании. Если терминал
это не поддерживает или нужно выделять без модификатора, нажмите `Alt+S`: мышь
будет временно передана терминалу, а строка состояния покажет режим выделения.
После копирования повторный `Alt+S` возвращает колесо к прокрутке чата.

После отправки сообщение сразу остаётся отдельным блоком с маркером `›`. Ответ
агента начинается с маркера `◆`, отделяется пустой строкой и появляется по мере
получения SSE-фрагментов от DeepSeek, а не целиком после завершения запроса.
Служебный JSON состояния при этом остаётся скрытым: в ленту потоково попадает
только значение поля `answer`. Поэтому введённый запрос виден и во время
рассуждения, и после получения ответа.

Поток используется одинаково для уточнения ещё не определённой задачи,
составления плана, реализации, validation и обычных ответов внутри этапа.
Инкрементальный JSON-декодер обрабатывает только новые байты, поэтому длинный
ответ не перечитывается целиком на каждом токене. Полноэкранный интерфейс
объединяет мелкие обновления и перерисовывается примерно раз в 25–40 мс либо
после 256 новых символов: большой буфер выводится быстрее, но текст продолжает
появляться небольшими порциями, а не одной «простынёй».

При вводе `/` над строкой состояния открывается палитра команд. Список
фильтруется по мере набора, `↑`/`↓` меняют выбранную команду, `Tab` дополняет,
`Enter` выбирает, а `Esc` закрывает палитру. Для `/pause` автодополнение оставляет
пробел, чтобы можно было дописать причину.

## Конфигурация

- `DEEPSEEK_API_KEY` — обязательный ключ;
- `DEEPSEEK_MODEL` — модель, по умолчанию `deepseek-chat`;
- `DEEPSEEK_BASE_URL` — OpenAI-совместимый endpoint DeepSeek;
- `AGENT_SYSTEM_PROMPT` — общая системная инструкция;
- `DATA_DIR` — каталог состояния, по умолчанию `./data`.

Состояние хранится в `DATA_DIR/task-state.json` и записывается атомарно с
правами `0600`. Последние шесть пар сообщений сохраняются ради продолжения
задачи; не вводите в диалог ключи, пароли и другие секреты.

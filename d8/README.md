# День 8 — токены в терминальном агенте

`/info` — список всех команд чата, параметры `/fill`, быстрые
действия заполнения и сочетания клавиш. Справка не вызывает API.

Основа — терминальный агент дня 7: потоковый ответ с Markdown, JSON-память,
сессии, одиночные запросы и очистка истории. Запуск всегда открывает терминальный чат.

Нужны Go 1.21+ и уже заданная в терминале переменная DEEPSEEK_API_KEY.

```sh
cd aiac9/d8
./mrkai
./mrkai -session study -prompt 'Объясни контекст LLM'
./mrkai -demo
```

Команды чата: /stats — расход за текущий запуск, /reset — очистить историю,
/exit или /quit — выйти. Ctrl+C также завершает программу.
История хранится в data/<session>.json; DATA_DIR меняет каталог.
mrkai привязывает каталог к своему расположению, включая запуск через symlink.
При go run . каталог данных отсчитывается от текущего рабочего каталога.

## Что считается

Перед каждым запросом выводятся:
- текущий текст пользователя;
- вся предыдущая история (без system и текущего запроса);
- системная инструкция;
- полный отправляемый вход с учётом служебного оформления;
- заполненность контекстного окна выбранной модели и резерв ответа, если он задан вручную.

Эти числа приблизительные: ceil(число UTF-8 байтов / 3), плюс условные
служебные токены на роли и сообщения. Это **не токенизатор DeepSeek**:
ошибка зависит от языка, кода и разметки. Компоненты включают разное
служебное оформление, поэтому их сумма может отличаться от полного входа.
Оценка не гарантирует, что запрос поместится в настоящее окно модели.

После ответа используются фактические prompt_tokens и completion_tokens
из usage API, включая последний SSE-фрагмент без choices. Если usage отсутствует,
вывод явно помечен как оценка. Расход ответа может включать скрытое рассуждение
модели, поэтому он не обязан совпадать с оценкой видимого текста.

За каждый ход и за запуск показываются токены и стоимость по заданным тарифам:
((вход − cache hit) × input-price + cache hit × cached-price +
ответ × output-price) / 1 000 000.

Тарифы в USD за миллион токенов выбираются автоматически по модели и времени
начала запроса (UTC). Флаги цен вручную переопределяют соответствующие компоненты.
Пример с **условными ручными** тарифами:

```sh
./mrkai -input-price 1 -cached-price 0.1 -output-price 2
```

История сохраняется между запусками, счётчики расхода — только за текущий запуск.
Вход включает повторно отправленную историю: каждый следующий ход снова
оплачивает её обработку, с учётом кеширования на стороне провайдера.
/reset очищает память, но не обнуляет уже потраченные за запуск токены.
Итоги могут смешивать API usage и оценки, если часть ответов пришла без usage.

## Лимиты и поведение при сбоях

Размер контекстного окна берётся из характеристик `DEEPSEEK_MODEL`.
Для поддерживаемых DeepSeek V4 API сообщает окно 1 048 576 токенов. По умолчанию
`max_tokens` не передаётся в API: длину ответа определяют модель и провайдер.
Только явно заданный `-max-tokens N` передаётся в запрос и резервируется
внутри контекстного окна.
Если модель неизвестна приложению, диалог работает, но `/fill` отключён:
приложение не подставляет ручной или вымышленный размер окна.

По умолчанию `allow-overflow=true`: весь контекст отправляется в API даже
при превышении локальной оценки. `/overflow off` или `-allow-overflow=false`
включает локальную блокировку; `/overflow on` возвращает отправку.
Режим действует до завершения программы. Ошибка API выводится с HTTP-кодом.
История остаётся целой, можно выполнить /reset или выбрать новую -session.
Автоматического сокращения истории нет: рост контекста виден напрямую.

При HTTP-ошибке API выводится ошибка, ход не сохраняется.
При обрыве потока частичный текст может быть виден, но в память не попадёт;
расход такого вызова неизвестен и отмечается отдельным счётчиком.
`finish_reason=length` означает обрезанный ответ: его usage учитывается,
но незавершённый ход не сохраняется. Диагностика показывает сработавший
`max_tokens` либо контекстный лимит, фактические токены входа и ответа,
настроенный предел ответа, контекстное окно и максимум ответа модели.
Если usage находится ниже известных границ, приложение прямо сообщает,
что API не уточнил причину, вместо предположения.
Проверка до вызова приблизительная, поэтому отказ API всё равно возможен.

Поля протокола проверены по
[документации Chat Completions DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/).

## Сравнение и сценарий для видео

```sh
./mrkai -demo
```

Демо работает без ключа, сети и файлов истории. Использует фиксированный ответ
имитатора, условные тарифы и бюджет 1600 токенов с резервом 128:
1. Короткий диалог — два коротких сообщения.
2. Длинный — восемь одинаковых сообщений: запрос остаётся одинаковым,
   но история, вход и накопленная стоимость растут.
3. Переполнение — большой запрос отклоняется до вызова модели;
   в памяти остаётся ноль сообщений.

Это демонстрация механики, а не измерение реальной модели.
Для видео сначала покажите демо, затем в живом чате несколько ходов и /stats.
Для демонстрации реального ограничения ответа задайте маленький -max-tokens
и попросите длинный текст. Для ошибки настоящего окна контекста отключите
локальную проверку и превысьте документированный лимит выбранной модели;
такой эксперимент может расходовать оплачиваемые токены.

Видео не включено: приведён готовый сценарий записи и воспроизводимое демо.

## Настройки и проверка

DEEPSEEK_MODEL по умолчанию deepseek-v4-flash (как в CLI дня 7),
DEEPSEEK_BASE_URL — https://api.deepseek.com/chat/completions,
AGENT_SYSTEM_PROMPT — системная инструкция. Полный список флагов: ./mrkai -help.
Никакие веб-серверы или браузерные интерфейсы не запускаются.

```sh
go test ./...
go vet ./...
```

Тесты используют имитацию HTTP-транспорта: проверяют usage в JSON и SSE,
кеш и стоимость, отсутствие usage, обрыв потока, обрезание ответа,
сохранность памяти при переполнении, терминальный ввод и Markdown.

## Быстрое заполнение окна из терминала

В чате показаны действия [+20%], [+50%], [+100%]. Введите подпись
без квадратных скобок и нажмите Enter. Это терминальные команды.
Размер окна определяется выбранной моделью автоматически:

```text
+20%
+20%
/context
+100%
Проверим, помещается ли запрос?
/reset
```

/fill 20 эквивалентна +20%; /fill без аргумента тоже добавляет 20%.
Можно указать любой целый процент от 1 до 100: /fill 35.
Прибавка считается от **полного окна**, а не от свободного остатка:
для окна 1 048 576 команда +20% добавляет 209 716 оценочных токенов
с учётом
оформления сообщения. Округление — вверх. Системная инструкция,
существующая история и заданный вручную резерв ответа учитываются отдельно.

Наполнитель — явно помеченное учебное сообщение пользователя; оно сохраняется
в истории и отправляется модели со следующим обычным запросом.
Само добавление не вызывает API и не увеличивает счётчики оплаченных токенов.
После каждой команды заполнения и по `/context` информационное поле показывает
состав локальной оценки: system, обычный диалог с числом сообщений, учебный
наполнитель с числом блоков, ручной резерв ответа (если задан) и свободный остаток либо величину
переполнения. Текст следующего запроса также займёт место.
Сразу после `/fill` дополнительно описывается созданный блок: `role=user`,
его доля модельного окна и оценочный размер, служебная метка, число повторов
` x`, сохранение в истории и отправка со следующим обычным сообщением.
Отдельно подтверждается, что сама команда заполнения API не вызывает.

Заполнение разрешено сверх 100%. В режиме `/overflow on` запрос дойдёт до API.
Добавляйте наполнитель до отказа API: локальная оценка токенов может отличаться
от точного токенизатора модели.
Число в ошибке API относится к одному текущему запросу: системная инструкция,
вся повторно отправленная история и новое сообщение. Это не сумма токенов всех
предыдущих API-вызовов. Для учебного наполнителя используется отдельная оценка,
приближенная к токенизации повторов ` x`; старый наполнитель из сохранённых
сессий с двойными пробелами распознаётся и пересчитывается примерно вдвое выше.
`/reset` удаляет всю историю, включая наполнитель, очищает видимую область
интерактивного терминала и scrollback. После очистки остаются подтверждение
и состояние пустого контекста. При выводе в pipe или файл управляющие
последовательности не добавляются. Проценты основаны на локальной оценке,
фактический токенизатор может иначе
обрабатывать повторяющийся текст. За одно действие разрешено не более
миллиона оценочных токенов; слишком маленькая прибавка, в которую не помещается
метка сообщения, отклоняется.

## Компактный вывод и редактирование строки

Под запросом выводятся две строки: оценка токенов запроса/истории/входа и
заполнение модельного окна. Без `-max-tokens` строка явно сообщает,
что ручного ограничения ответа нет.
Под ответом — токены входа и ответа, стоимость хода, затем итог за запуск.
Подробные счётчики, включая неизвестный расход при сбоях, доступны через /stats.
Префикса «Вы>» нет. Четыре визуальные зоны:
- «ВВОД» — жёлтая линия и боковая черта у редактируемого текста;
- «СООБЩЕНИЕ» — голубая линия над полным отправленным текстом;
- «ОТВЕТ» — зелёная линия над потоковым ответом;
- статистика — приглушённые строки с маркером «·» под сообщением и ответом.

После Enter временное поле ввода заменяется отправленным сообщением.
Команды отмечены отдельно. При NO_COLOR и выводе в файл цвет отключается,
но подписи, линии и маркеры остаются.

При интерактивном запуске на macOS/Linux:
- ↑ — предыдущее сообщение; повторные нажатия перебирают более старые;
- ↓ — более новое сообщение; после последнего возвращается исходный черновик;
- Enter — отправить выбранный или отредактированный текст;
- Ctrl+Backspace / Ctrl+U — удалить всю вводимую строку;
- Backspace — удалить последний символ;
- Ctrl+D на пустой строке или Ctrl+C — выйти.

История навигации содержит сообщения пользователя, включая неудачные запросы
текущего запуска. При старте восстанавливаются сообщения из сохранённого диалога.
Команды и учебный наполнитель в перебор не попадают. /reset очищает контекст
модели; история ввода текущего запуска остаётся доступной стрелками.

Поддерживаются BS и распространённые расширенные escape-последовательности
Ctrl+Backspace. Если терминал передаёт тот же DEL, что и для обычного Backspace,
используйте Ctrl+U или настройте отправку 0x08 для Ctrl+Backspace.

Поле ввода занимает ширину терминала. Длинная строка прокручивается по
горизонтали; ширина пересчитывается при вводе после изменения размера окна.
После Enter выводится полное сообщение. Текст сохраняется целиком (до 262144 вводимых символов).
Редактирование выполняется в конце строки. Настройки терминала восстанавливаются
при штатном выходе и Ctrl+C. Ввод из pipe работает построчно.


## Реальная стоимость API

Обычный запуск ./mrkai больше не требует флагов цен. Используются тарифы из
https://api-docs.deepseek.com/quick_start/pricing/ (проверены 9 сентября 2026).
За миллион токенов, USD:

| Модель | Вход без кеша off-peak / peak | Кеш off-peak / peak | Ответ off-peak / peak |
| --- | --- | --- | --- |
| deepseek-v4-flash | 0.22 / 0.44 | 0.007 / 0.014 | 0.66 / 1.32 |
| deepseek-v4-pro | 0.66 / 1.32 | 0.022 / 0.044 | 1.98 / 3.96 |
| deepseek-v4-flash-vision-exp | 0.22 / 0.44 | 0.007 / 0.014 | 0.66 / 1.32 |

Peak: понедельник–пятница, 01:00–04:00 и 06:00–10:00 UTC.
Для каждого запроса тариф выбирается заново по времени отправки;
во время получения ответа он не меняется. На границе тарифных периодов
момент учёта запроса провайдером может отличаться от локального времени отправки.

Под ответом отдельно видна стоимость входа (вся история + запрос, с учётом кеша)
и выхода, сумма хода и сумма за запуск. Это расчёт по официальному тарифу и usage,
а не проверка списаний в аккаунте. Льготы, индивидуальные скидки и баланс
не запрашиваются. Без usage используются оценки, число таких ходов видно в итогах.

Для неизвестной модели или другого API нужны все три ручных тарифа.
При смене официальных цен обновите pricing.go либо передайте флаги.
Чтобы использовать автоматические цены, уберите прежние -input-price,
-cached-price и -output-price из команды запуска. Явный ноль считается ручной ценой.

## Ожидание и потоковый ответ

После отправки запроса и до первого текстового фрагмента терминал показывает
живой таймер `• Working (2m 30s • esc to interrupt)`. `Esc` отменяет текущий
HTTP-запрос, не закрывает агент и возвращает новое поле ввода. При появлении
первого фрагмента строка ожидания удаляется, после чего ответ выводится сразу
по мере прихода SSE-фрагментов. В pipe и файлах лоадер не печатается.

Потоковая обработка проверяется тестом с управляемым SSE-потоком: первая часть
обязана попасть в callback до отправки завершающей части и `[DONE]`.
